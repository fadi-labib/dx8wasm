# Design — Phase 2 slice (milestones 2.0–2.2): D3D8 device + Clear/Present on WebGL2

Status: **proposed** (awaiting review). Scope: the first vertical slice of Phase 2
(runtime translation layer). See `docs/PHASE2_PLAN.md` for the full-phase plan and
`SPEC.md` §6–7 for context.

## 1. Goal & success criterion

Prove the whole bottom of the Phase 2 stack with one demonstrable behavior:
**our own C++, compiled to wasm, calls the real D3D8 entry points —
`Direct3DCreate8()` → `CreateDevice()` → `Clear(known color)` → `Present()` — and
a headless-Chromium test reads back the framebuffer and asserts the pixel.**

Green means the toolchain, the SDL3-backed WebGL2 context, the COM object model,
and the pixel-readback verification rig all work — the foundation every later
milestone (buffers → FVF → textures → coverage) builds on.

## 2. Scope

**In scope:** Emscripten toolchain + pinned `emsdk`; SDL3 platform layer bringing
up a WebGL2 context; clean-room `d3d8.h` for the subset used; `IDirect3D8` +
`IDirect3DDevice8` implementing device creation, `Clear`, `Present`, `Release`;
two smoke programs; a Playwright pixel-readback test.

**Out of scope (later milestones):** vertex/index buffers, FVF, `DrawIndexedPrimitive`
(2.3); textures (2.4); coverage/fallback hooks (2.5); render-state subset,
depth/blend/cull/alpha-test (2.6); real windowing/input; real Generals vtable
compatibility validation.

## 3. Decisions (locked in brainstorming)

| # | Decision | Rationale |
|---|---|---|
| Scope | Vertical slice 2.0–2.2 | Demonstrable unit; forces the real ABI decisions without over-scoping one spec. |
| D3D8 headers | **Clean-room declare our subset** | Consistent with the project's clean-room stance; smallest owned surface; no third-party header license to track. |
| GL context | **SDL3 now** (not raw-GL-deferred) | User choice: more representative of the final architecture; platform layer stood up early. Cost: SDL3-to-wasm build before first pixel. |
| Target | Generals | Coverage tracks Generals' D3D8 surface (later milestones); this slice uses synthetic clears. |
| Verify | Headless-Chromium pixel readback | Already de-risked: SwiftShader gives a real WebGL2 context; `glReadPixels` returns exact bytes. |
| Diagnostics | **Two smoke targets** (`gl_smoke`, `d3d8_smoke`) | Isolate toolchain/rig failures from `d3d8webgl` failures. |

## 4. Architecture & layering

```
runtime/test/{gl_smoke,d3d8_smoke}.cpp   ← the "game": calls the API, reads back, reports to JS
        │  Direct3DCreate8() / IDirect3DDevice8::Clear,Present
        ▼
runtime/d3d8/  d3d8.h                     ← clean-room COM ABI contract (our declarations)
        ▼
runtime/d3d8webgl/  (implementation)      ← IDirect3D8, IDirect3DDevice8 on WebGL2
        │  platform_gl_* seam
        ▼
runtime/platform/  (SDL3)                 ← SDL window + WebGL2 context on #canvas
        ▼
WebGL2 (browser)  ──glReadPixels──▶ JS ──▶ Playwright assert
```

Each layer has one job and a narrow interface: `platform` yields a current GL
context; `d3d8webgl` implements COM on top; `d3d8.h` is the frozen contract
between caller and runtime.

| File | Purpose |

| `runtime/platform/platform.h`, `platform_sdl3.cpp` | Seam: SDL3 window + WebGL2 context on `#canvas`; make-current / present. |
| `runtime/test/gl_smoke.cpp` | Raw-GL clear + readback — proves toolchain + context + rig. |
| `runtime/test/d3d8_smoke.cpp` | Drives the D3D8 path; `glReadPixels`; reports pixel to JS. |

## 6. Data flow & error handling

Happy path (in the browser, inside the smoke's `main()`):
`Direct3DCreate8` → `IDirect3D8::CreateDevice` (device grabs the SDL3 WebGL2
context) → `device->Clear(D3DCLEAR_TARGET, knownColor)` (→ `glClearColor`+`glClear`)
→ `device->Present()` (→ `SDL_GL_SwapWindow`/commit) → `glReadPixels(0,0,1,1)` →
`EM_JS report_pixel` → `window.__gpu`.

Errors: every COM entry returns `HRESULT`; failures set `window.__gpu.error =
"<message>"` instead of a pixel, so the test fails with a diagnosis, not a hang.
`HWND`/focus-window are opaque stubs from `platform`. Because the header declares
only implemented methods, there are no unimplemented pure-virtuals to trap; the
coverage/unhandled hooks (`contract.h`) are correctly deferred to milestone 2.5.

## 7. Testing

`web-runtime/test/phase2.gpu.test.mjs` builds (two-step: source `emsdk_env.sh` →
`cmake --preset emscripten && cmake --build`), serves `build/emscripten/`, launches
headless Chromium with the SwiftShader flags (`--use-gl=angle
--use-angle=swiftshader --enable-unsafe-swiftshader`, verified working), loads each
smoke, waits for `window.__gpu`, and asserts:
- `gl_smoke`: cleared pixel ≈ known color within ±2 (software rendering is
  deterministic), no error.
- `d3d8_smoke`: same assertion, through the D3D8 API.

If `gl_smoke` passes and `d3d8_smoke` fails, the defect is in `d3d8webgl`.

## 8. Risks

- **SDL3-to-wasm (top risk).** Emscripten ships an SDL3 port (`--use-port=sdl3` on
  recent toolchains); implementation must first confirm the freshly-installed
  emsdk has it, else build SDL3 from source (Emscripten backend is supported).
- **COM/vtable ABI.** Smoke and runtime are both built with `emcc`, so a C++
  pure-virtual interface produces matching Itanium-ABI vtables — no hand-rolled
  vtables. Self-consistent for this slice; real-Generals compatibility is a later
  milestone.
- **Readback color space.** Assert with ±2 tolerance; sRGB default-FB handling
  (the `contract.h` `srgb` flag) is decided when it first matters.

## 9. Deliverable

`npm run` (or a documented build+test command) shows both smokes green: our C++
clears a WebGL2 canvas — one via raw GL, one via the D3D8 `Clear`/`Present` path —
verified by headless pixel readback. That closes milestones 2.0–2.2.
